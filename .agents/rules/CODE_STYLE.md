# Code Style Rules

- ALWAYS use guard clauses to handle errors and edge cases.
- DO NOT use nested if statements; instead, use guard clauses or early returns.
- Use descriptive variable and function names that clearly convey their purpose.
- Use comments to explain complex logic, but avoid obvious comments that state the obvious.
- Keep functions and methods short and focused on a single task; if a function is too long, consider breaking it into smaller helper functions.
- Use consistent naming conventions (e.g., camelCase for variables and functions, PascalCase for classes).
- For Dtos variables, do not use the prefix "dto" in the variable name; instead, use a descriptive name that reflects the purpose of the variable.
